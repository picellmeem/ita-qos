## 📜 สคริปต์เต็ม (พูดประมาณ 5 นาที)

### [สไลด์ 1 — ปก] (15 วินาที)

> "สวัสดีครับ/ค่ะ ผม/ดิฉัน [ชื่อ] จาก [คณะ/มหาวิทยาลัย]
> วันนี้จะนำเสนอผลงานชื่อ **ITA-QOS** — Integrated Temporal Analytics for Quality and Operational Safety
> ระบบติดตามยาและเครื่องมือแพทย์ด้วย NFC ที่ออกแบบมาเพื่อโรงพยาบาลโดยเฉพาะ"

### [สไลด์ 2 — Hook] (30 วินาที)

> "เริ่มจากตัวเลขที่หลายท่านอาจไม่รู้ —
> **โรงพยาบาลในไทยทิ้งยาหมดอายุปีละหลายร้อยล้านบาท**
> และอุบัติเหตุจาก medication error เป็นสาเหตุการเสียชีวิตอันดับ 3 ในระบบสาธารณสุขทั่วโลก
>
> สาเหตุหลักของทั้งสองอย่างคือ — เราไม่มีระบบที่ติดตามได้แบบ real-time"

### [สไลด์ 3 — ปัญหา] (45 วินาที)

> "ปัญหาที่เจอจริงในโรงพยาบาลมี 3 อย่าง:
>
> 1. **ยาบนชั้นมีเป็นพันรายการ** — เช็ควันหมดอายุด้วยมือ พลาดง่าย เสี่ยงให้คนไข้
>
> 2. **เครื่อง CT, MRI ลืมรอบบำรุง** — พังกระทันหันตอนใช้งานจริง = ปิดบริการ + ค่าซ่อมหลักล้าน
>
> 3. **ระบบกระจัดกระจาย** — Excel หลายไฟล์ คนละแผนกใช้คนละแบบ ไม่มี source of truth
>
> เราเลยถามตัวเองว่า — ถ้าทุกขวดยา ทุกเครื่องจักร แตะมือถือแล้วเห็นข้อมูลทันที จะเป็นยังไง?"

### [สไลด์ 4 — Target Users] (30 วินาที)

> "ระบบนี้ออกแบบสำหรับ 4 กลุ่ม:
> - **เภสัชกร** — แก้ไขข้อมูลยา
> - **ทีมซ่อมบำรุง** — แก้ไขเครื่อง
> - **พยาบาล/บุคลากรทางการแพทย์** — แตะดูข้อมูล
> - **ผู้บริหาร** — ดู Dashboard ภาพรวม
>
> แต่ละกลุ่มมีสิทธิ์แตกต่างกัน ป้องกันการแก้ข้ามแผนก"

### [สไลด์ 5 — Solution] (45 วินาที)

> "ITA-QOS ใช้ 3 เทคโนโลยีหลัก:
>
> **1. NFC Tag** — ติดบนยาหรือเครื่อง แตะมือถือ 1 วินาทีเห็นข้อมูล
> **2. Web Application** — ใช้ทั้ง desktop และมือถือ ไม่ต้องลงแอพ
> **3. ระบบสีสถานะ 3 ระดับ** — เขียว/เหลือง/แดง — เห็นปุ๊บเข้าใจปั๊บ
>
> สิ่งสำคัญที่สุดคือ — **ใครก็ตามที่แตะ NFC tag จะเห็นข้อมูลทันที โดยไม่ต้อง login**
> ตอบโจทย์การใช้งานจริง ที่พยาบาลรีบหยิบยา ไม่มีเวลามา login"

### [สไลด์ 6 — Demo] (60 วินาที — เปิดวิดีโอ screen recording)

> "ขอเปิดวิดีโอ demo ให้ดู 1 นาที"
>
> [โชว์ flow: scan QR → เห็นหน้ายา → กลับมา dashboard เห็นกราฟ → คลิกปุ่ม print sticker → จบ]
>
> "นี่คือ flow จริงตั้งแต่ต้นจนจบ"

### [สไลด์ 7 — Tech Stack] (30 วินาที)

> "ฝั่งเทคโนโลยี เราใช้ stack ที่ทันสมัยและขยายได้:
>
> - **Next.js 15** — React framework ของ Vercel
> - **Supabase** — Database + Auth + Realtime ในตัว
> - **PostgreSQL Row Level Security** — บังคับสิทธิ์ที่ database ไม่ใช่แค่โค้ด
> - **Tailwind + Recharts** — UI สวยและ chart interactive
>
> ทั้งหมด deploy บน cloud — **ไม่ต้องลงทุน server**"

### [สไลด์ 8 — Differentiation] (30 วินาที)

> "เทียบกับระบบที่มีอยู่:
>
> - **HIS เดิมของโรงพยาบาล** — ไม่มี NFC, UI เก่า, ไม่มี dashboard real-time
> - **Excel** — ไม่ปลอดภัย, ไม่ติดตาม audit ได้
> - **ระบบ ERP ต่างประเทศ** — แพง, ติดตั้งยาก, ไม่รองรับภาษาไทย
>
> ITA-QOS เน้น **ใช้ง่าย + เริ่มต้นใช้ได้ทันที + ฟรี**"

### [สไลด์ 9 — ROI] (45 วินาที)

> "ในแง่คุณค่าทางคลินิก:
>
> - ลดยาหมดอายุที่ไม่รู้ตัว — ประหยัดเฉลี่ย **300,000-500,000 บาท/ปี/แผนก**
> - ลด medication error ได้ **30-50%** จาก visibility ที่เพิ่มขึ้น
> - เครื่องไม่พังกระทันหัน — ลด downtime **70%**
> - บุคลากรประหยัดเวลาค้นหา **15 นาที/วัน/คน**
>
> ROI ภายใน 6 เดือนสำหรับโรงพยาบาลขนาดกลาง"

### [สไลด์ 10 — Roadmap] (20 วินาที)

> "Phase 1 ทำเสร็จแล้ววันนี้
> Phase 2 จะเพิ่ม Email/LINE alert + Mobile app
> Phase 3 ใช้ AI ทำนายความน่าจะเป็นที่เครื่องจะพัง"

### [สไลด์ 11 — Business] (20 วินาที — เผื่อมีโอกาสแข่งต่อ)

> "ถ้าจะ commercial — model SaaS ราคา 5,000-15,000 บาท/เดือน/โรงพยาบาล

### [สไลด์ 12 — ปิด] (15 วินาที)

## 🎯 จุดเน้นสำคัญ (สำหรับกรรมการแต่ละกลุ่ม)

### กรรมการอาจารย์ด้านวิทย์สุขภาพ
- ✅ เน้น "ลด medication error" + "patient safety"
- ✅ ตัวอย่างเคสจริง — Lorazepam (ยาควบคุมพิเศษ) หมดอายุ ถ้าไม่รู้คนไข้อาจได้รับยาไม่มีฤทธิ์
- ✅ พูดเรื่อง compliance (HA, JCI standard)
- ❌ อย่าลึกเรื่อง code

### กรรมการผู้เชี่ยวชาญด้านเทค
- ✅ เน้น Architecture: RLS, Next.js Server Actions, Edge functions
- ✅ Security: Auth + Audit log + ไม่มี SQL ที่ raw
- ✅ Scalable: Serverless, ใช้แค่ DB ก็เพิ่ม user ได้ไม่จำกัด
- ✅ Open source friendly

## 🛡️ Q&A เตรียมรับมือ

### "ทำไมไม่ใช้ HIS เดิมของโรงพยาบาล?"
> "HIS ส่วนใหญ่ออกแบบสำหรับ billing/EHR ไม่ได้เน้น operational tracking
> และ HIS แทบทุกตัวไม่รองรับ NFC + ไม่มี mobile-first interface
> ITA-QOS เป็น **layer เสริม** ไม่ใช่ replacement
> ในอนาคตจะ integrate กับ HIS ผ่าน HL7 FHIR ได้"

### "ความปลอดภัย — ใครเข้าได้บ้าง?"
> "เราใช้ **3 ชั้น**:
> 1. Authentication ด้วย Supabase Auth (industry standard)
> 2. Row Level Security ที่ database ระดับ row-by-row
> 3. Audit log ทุก action — ใครแก้อะไรเมื่อไร
>
> ส่วนหน้า scan QR สาธารณะ จะแสดงเฉพาะ **read-only** — แก้ไขต้อง login + role"

### "NFC ใช้ได้กับมือถือทุกเครื่องมั้ย?"
> "Android ตั้งแต่ปี 2014 ขึ้นไปทั้งหมดรองรับ NFC
> iPhone 7 ขึ้นไปก็รองรับแต่ workflow ต่างนิดหน่อย
> **เราเลยมี QR code เป็น fallback** — ทุกเครื่องที่มีกล้อง scan ได้"

### "ราคา NFC tag เท่าไร?"
> "NTAG215 ราคาประมาณ 12-20 บาท/ดวง
> โรงพยาบาลกลางใช้ประมาณ 5,000 ดวง = ~75,000 บาท ลงทุนครั้งเดียว"

### "ถ้า server ล่ม / Vercel ล่ม?"
> "Vercel uptime 99.99% (SLA)
> Supabase มี automated backup + point-in-time recovery
> ในกรณีฉุกเฉิน เภสัชกรยังเช็คยาด้วยตาได้ — ระบบเรา **augment** ไม่ใช่ **replace**"

### "ทำไมเลือก Supabase ไม่เลือก Firebase?"
> "Supabase ใช้ PostgreSQL — relational database ที่ปรับ schema + เขียน complex query ได้
> Firebase เป็น NoSQL ไม่เหมาะกับข้อมูลที่มี relationship เยอะแบบยา-lot-location
> และ Supabase open-source — ย้ายออกได้ตลอด ไม่ vendor lock-in"

### "ภาษาไทย/ภาษาอื่นรองรับมั้ย?"
> "ตอนนี้ภาษาไทย + อังกฤษ
> Phase 2 จะมี i18n สำหรับภาษาอื่น — ตลาด ASEAN"

### "ใครเป็นเจ้าของข้อมูล?"
> "**โรงพยาบาล** — เราใช้ Supabase ของโรงพยาบาลเอง หรือ self-host ได้ (Supabase open-source)
> ข้อมูลคนไข้ไม่ออกจาก infrastructure ของโรงพยาบาล"

### "นวัตกรรมจริงๆ ของโปรเจกต์คืออะไร?"
> "ไม่ใช่ NFC อย่างเดียว — NFC มีในตลาดแล้ว
> **นวัตกรรมคือ การรวม 3 อย่าง:**
> 1. NFC tap ที่ไม่ต้อง login (universal access)
> 2. RLS ที่บังคับสิทธิ์ที่ DB (ไม่ใช่ใน app)
> 3. Temporal status engine — คำนวณสีอัตโนมัติจากวันที่
>
> ทำให้ระบบ secure + scalable + simple พร้อมกัน"
